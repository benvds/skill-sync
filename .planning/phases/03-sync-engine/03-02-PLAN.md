  <name>Task 1: Add dialoguer dependency and implement orphan scan, temp cleanup, and sync orchestration in sync.rs</name>
  <files>Cargo.toml, src/sync.rs</files>
  <action>
    1. Add dialoguer to Cargo.toml dependencies:
       ```toml
       dialoguer = "0.12"
       ```

    2. Add the following public functions to src/sync.rs:

    a. `pub fn cleanup_stale_temp_dirs(target_dir: &Path)`:
       - Read entries in target_dir (if it exists — return silently if not)
       - For each entry whose name starts with ".skills-sync-tmp-", call `fs::remove_dir_all`
       - Log each cleanup to stderr: `eprintln!("cleaned up stale temp dir: {}", name)`
       - Ignore errors on cleanup (best-effort: `let _ = fs::remove_dir_all(...)`)

    b. Define a struct for orphan info:
       ```rust
       pub struct OrphanSkill {
           pub dir_path: PathBuf,
           pub dir_name: String,
           pub source: String,
       }
       ```

    c. `pub fn scan_orphans(target_dir: &Path, manifest_repos: &std::collections::HashSet<String>) -> Vec<OrphanSkill>`:
       - Read all entries in target_dir (return empty Vec if dir doesn't exist)
       - Skip entries starting with ".skills-sync-tmp-" (temp dirs)
       - For each remaining directory, check for META_FILENAME (.skills.lock) inside it
       - If metadata exists and its `source` field is NOT in `manifest_repos`, add to orphans list
       - Return collected orphans sorted by dir_name for deterministic output

    d. `fn prompt_orphan_removal(orphans: &[OrphanSkill]) -> bool`:
       - Print orphan list to stderr:
         ```
         warning: N orphaned skill(s) found:
           dir_name (source)
           dir_name (source)
         ```
       - Use `dialoguer::Confirm::new().with_prompt("Remove orphaned skills?").default(false).interact_opt()`
       - Handle result: `Ok(Some(true))` -> return true, everything else -> return false
       - This handles non-TTY terminals gracefully (interact_opt returns Err, we default to false)

    e. `pub fn execute_sync_plan(actions: &[crate::resolver::SyncAction], target_dir: &Path, token: Option<&str>, branch_map: &std::collections::HashMap<String, String>, manifest_repos: &std::collections::HashSet<String>) -> crate::error::Result<()>`:
       - Call `cleanup_stale_temp_dirs(target_dir)` first
       - Create target_dir if it doesn't exist: `fs::create_dir_all(target_dir)` (ignore if already exists)
       - Track `failed_skills: Vec<String>` and `succeeded: usize` counters
       - Process actions sequentially (CONTEXT: one skill at a time):
         - `SyncAction::Install { repo, subdirectory, remote_sha }`:
           - Get branch from branch_map (default to "main" if missing — shouldn't happen but be defensive)
           - Call `execute_install(repo, subdirectory, remote_sha, branch, target_dir, token)`
           - On success: print `installed: {skill_dir_name}`, increment succeeded
           - On error: `eprintln!("warning: failed to install {}: {}", skill_dir_name, err)`, add to failed_skills
         - `SyncAction::Update { repo, subdirectory, new_sha, .. }`:
           - Get branch from branch_map
           - Call `execute_update(repo, subdirectory, new_sha, branch, target_dir, token)`
           - On success: print `updated: {skill_dir_name}`, increment succeeded
           - On error: warn and add to failed_skills
         - `SyncAction::Remove { repo, subdirectory, .. }`:
           - Collect into a separate removals list (handled together with global orphans below)
         - `SyncAction::Skip { .. }`:
           - No action needed
       - After processing installs/updates, scan for global orphans:
         - `let global_orphans = scan_orphans(target_dir, manifest_repos)`
         - Combine resolver Remove actions with global orphans into a single orphan list
         - For resolver Remove actions, convert to OrphanSkill (dir_path from target_dir + skill_dir_name, source from repo)
         - If combined orphan list is non-empty, call `prompt_orphan_removal(&all_orphans)`
         - If confirmed, delete each orphan via `execute_remove(&orphan.dir_path)`, count successes and failures
       - Print summary to stderr: `sync complete: {succeeded} succeeded, {failed} failed`
       - If any skills failed, return `Err(SkillsSyncError::SyncFailed { repo: "multiple", reason: format!("{} skill(s) failed to sync", failed_count) })`
       - Otherwise return Ok(())
  </action>

    3. After the sync plan summary print (the existing `println!("sync plan: ...")` block), add sync execution:
       ```rust
       // Execute sync plan
       if installs > 0 || updates > 0 || removes > 0 {
           let target_dir = std::path::Path::new(".claude/skills");
           let sync_token = {
               let (t, _) = github::discover_token();
               t
           };
           sync::execute_sync_plan(
               &all_actions,
               target_dir,
               sync_token.as_deref(),
               &branch_map,
               &manifest_repos,
           )?;
       } else {
           // Still run orphan scan even when no install/update/remove actions
           let target_dir = std::path::Path::new(".claude/skills");
           sync::cleanup_stale_temp_dirs(target_dir);
           let orphans = sync::scan_orphans(target_dir, &manifest_repos);
           if !orphans.is_empty() {
               // execute_sync_plan handles orphan prompting, but when there are no
               // other actions we handle it inline
               sync::execute_sync_plan(
                   &all_actions,  // empty or skip-only
                   target_dir,
                   None,
                   &branch_map,
                   &manifest_repos,
               )?;
           }
       }
       ```

       Wait — actually, it is simpler to ALWAYS call execute_sync_plan. The function already handles skip-only and empty action lists gracefully (it just does temp cleanup and orphan scan). Simplify to:

       ```rust
       // Execute sync plan (handles install, update, remove, and orphan detection)
       let target_dir = std::path::Path::new(".claude/skills");
       sync::execute_sync_plan(
           &all_actions,
           target_dir,
           token.as_deref(),   // reuse token from GitHubClient construction above
           &branch_map,
           &manifest_repos,
       )?;
       ```

       Place this AFTER the sync plan summary print and BEFORE the failed_repos exit-code check.

       Note: Reuse the `token` variable already extracted from `github::discover_token()` earlier in run(). Do NOT call discover_token() a second time.

    4. Adjust the failed_repos error check: The sync engine's execute_sync_plan already returns Err for sync failures. The existing `failed_repos` check handles API-level failures (repos that couldn't be fetched). Keep both — they are different failure categories. The final exit code should be non-zero if either API failures or sync failures occurred.

    5. IMPORTANT: The `token` variable used in `GitHubClient::new(token, auth_method)` is moved into the client. To also pass it to the sync engine, either:
       - Clone the token before passing to GitHubClient: `let sync_token = token.clone();` before `let client = github::GitHubClient::new(token, auth_method)...`
       - Or extract token from the client (if it has a getter)

       Since GitHubClient doesn't expose the token, clone it before constructing the client:
       ```rust
       let sync_token = token.clone();
       let client = github::GitHubClient::new(token, auth_method)...
       // ... later ...
       sync::execute_sync_plan(&all_actions, target_dir, sync_token.as_deref(), &branch_map, &manifest_repos)?;
       ```
