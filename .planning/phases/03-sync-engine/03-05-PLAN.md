<objective>
Move per-skill metadata lock files from inside the skill directory to sibling files at the target directory level.

**Design decision revision:** The original CONTEXT.md decision states "Lock file (.skills.lock) lives inside the skill directory — self-contained." This plan intentionally revises that decision based on UAT findings where the user explicitly expected metadata at the target directory level, not buried inside cloned skill content. The UAT evidence (user feedback during Phase 03 verification) takes precedence over the original design decision.

Purpose: Close MAJOR gap — the user expected metadata at the project/global directory level, not buried inside the cloned skill content. Moving lock files to `target_dir/owner--repo.lock` (alongside `target_dir/owner--repo/`) separates sync metadata from skill content while preserving per-skill atomicity.
Output: Updated metadata path computation, sync operations, orphan detection, and local metadata loading — all using sibling lock file paths.
</objective>

       fn load_local_metadata(repo: &str, target_dir: &std::path::Path) -> HashMap<String, metadata::SkillMeta> {
           let mut result = HashMap::new();

           if !target_dir.exists() {
               return result;
           }

           if let Ok(entries) = std::fs::read_dir(target_dir) {
               for entry in entries.flatten() {
                   let path = entry.path();
                   // Look for sibling lock files (*.lock) instead of lock files inside directories
                   if path.is_file() {
                       if let Some(ext) = path.extension() {
                           if ext == metadata::META_EXTENSION {

                                   if meta.source == repo {
                                       let key = skill_key(repo, &meta.subdirectory);
