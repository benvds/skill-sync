<task type="auto" tdd="true">
  <name>Task 1: Implement skill detection from tree data</name>
  <files>src/resolver.rs, src/lib.rs, tests/resolver_tests.rs</files>
  <behavior>
    - detect_root_skill: tree with "SKILL.md" blob at root → returns one RemoteSkill with subdirectory=None
    - detect_root_skill_wins: tree with root SKILL.md AND subdir/SKILL.md → returns only root skill, ignores subdirectory
    - detect_monorepo_skills: tree with "alpha/SKILL.md" and "beta/SKILL.md" blobs (no root SKILL.md) → returns two RemoteSkill entries with subdirectory=Some("alpha") and Some("beta")
    - detect_no_skills: tree with no SKILL.md entries → returns empty Vec
    - detect_ignores_deep_nesting: tree with "a/b/SKILL.md" (two levels deep) → not detected (only one level deep)
    - detect_ignores_tree_type: tree entry with path="SKILL.md" but type="tree" (directory) → not detected (must be "blob")
    - detect_monorepo_sha: each RemoteSkill carries the tree SHA from the parent TreeResponse for change detection
  </behavior>
  <action>
    1. Create src/resolver.rs with:
       - `RemoteSkill` struct (Debug, Clone, PartialEq): subdirectory (Option<String>), tree_sha (String)
       - `detect_skills(tree: &TreeResponse) -> Vec<RemoteSkill>` function:
         a. Check for root SKILL.md: iterate tree entries, find any with `path == "SKILL.md"` AND `entry_type == "blob"`. If found, return vec with single RemoteSkill { subdirectory: None, tree_sha: tree.sha.clone() }.
         b. If no root SKILL.md, scan for one-level-deep: filter entries where `entry_type == "blob"` AND path ends with "/SKILL.md" AND path has exactly one '/' character. For each match, extract subdirectory name by stripping "/SKILL.md" suffix.
         c. Return vec of RemoteSkill { subdirectory: Some(subdir), tree_sha: tree.sha.clone() } for each match.

    2. Add `pub mod resolver;` to src/lib.rs (after `pub mod github;`)

    3. Write tests in tests/resolver_tests.rs — build TreeResponse structs manually for each test case. Helper function `make_tree(entries: &[(&str, &str)]) -> TreeResponse` that creates a TreeResponse with given (path, type) pairs and a fixed test SHA.
  </action>
  <verify>
    <automated>cargo test --test resolver_tests</automated>
  </verify>
  <done>
    - detect_skills correctly identifies single-skill repos, monorepos, empty repos
    - Root SKILL.md always wins over subdirectory skills
    - Only one-level-deep subdirectories detected (no deep nesting)
    - Only blob type entries considered (not tree or commit)
  </done>

<task type="auto" tdd="true">
  <name>Task 2: Implement sync resolution logic</name>
  <files>src/resolver.rs, tests/resolver_tests.rs</files>
  <behavior>
    - resolve_install_new_skill: remote skill not in local metadata → SyncAction::Install
    - resolve_update_changed_sha: remote skill in local metadata with different sha → SyncAction::Update with old and new sha
    - resolve_skip_unchanged: remote skill in local metadata with same sha → SyncAction::Skip
    - resolve_remove_orphan: local skill (source matches repo) not in remote skills → SyncAction::Remove
    - resolve_multiple_actions: mix of install, update, skip, remove in one resolve call
    - resolve_idempotent: calling resolve twice with same inputs returns same actions
    - resolve_monorepo_skill_key: skills from same repo but different subdirectories are tracked independently
    - resolve_remove_only_from_same_repo: orphan detection only removes skills whose source matches the current repo, not skills from other repos
  </behavior>
  <action>
    1. Add to src/resolver.rs:
       - `SyncAction` enum (Debug, Clone, PartialEq):
         - `Install { repo: String, subdirectory: Option<String>, remote_sha: String }` — new skill to install
         - `Update { repo: String, subdirectory: Option<String>, old_sha: String, new_sha: String }` — existing skill with changed SHA
         - `Remove { repo: String, subdirectory: Option<String>, local_sha: String }` — orphaned skill to remove
         - `Skip { repo: String, subdirectory: Option<String>, sha: String }` — unchanged skill
       - `RepoSkills` struct: repo (String), skills (Vec<RemoteSkill>), commit_sha (String) — groups a repo's remote skills with its HEAD commit SHA
       - `resolve(repo_skills: &RepoSkills, local_metadata: &HashMap<String, SkillMeta>) -> Vec<SyncAction>` function:
         a. For each remote skill in repo_skills.skills:
            - Build skill key: if subdirectory is Some(s), key = "{repo}/{s}"; else key = "{repo}"
            - Look up key in local_metadata
            - If not found → Install { repo, subdirectory, remote_sha: repo_skills.commit_sha }
            - If found and meta.sha != repo_skills.commit_sha → Update { repo, subdirectory, old_sha: meta.sha, new_sha: repo_skills.commit_sha }
            - If found and meta.sha == repo_skills.commit_sha → Skip { repo, subdirectory, sha }
         b. For orphan detection: iterate local_metadata, find entries where meta.source == repo AND the key is not matched by any remote skill. For each → Remove { repo, subdirectory: meta.subdirectory, local_sha: meta.sha }
         c. Return collected actions

       - `skill_key(repo: &str, subdirectory: &Option<String>) -> String` helper — builds the lookup key used to match remote skills against local metadata

    2. Add resolve tests to tests/resolver_tests.rs using HashMap<String, SkillMeta> for local state. Use SkillMeta::new() to construct test metadata.
  </action>
  <verify>
    <automated>cargo test --test resolver_tests</automated>
  </verify>
  <done>
    - resolve produces correct Install/Update/Remove/Skip actions
    - Orphan detection only affects skills from the same repo
    - Idempotency: same inputs always produce same outputs
    - Monorepo skills tracked independently by subdirectory
    - All existing tests continue to pass
  </done>
</task>
