```rust
pub fn run_git(args: &[&str], cwd: Option<&Path>, verbose: bool) -> crate::error::Result<()> {
    let mut cmd = Command::new("git");
    cmd.args(args).stdout(Stdio::null());
    if verbose {
        cmd.stderr(Stdio::inherit());
    } else {
        cmd.stderr(Stdio::piped());
```

Wait — changing `run_git` signature would break all callers. Instead, add a separate helper or pass verbose through the sync functions. The cleanest approach: add a module-level or parameter approach.

**Revised approach:** Add a `verbose` parameter to `execute_install` and `execute_update` (which already have many params). They pass it to `run_git`. Change `run_git` to accept verbose:

- Update `run_git` signature: `pub fn run_git(args: &[&str], cwd: Option<&Path>, verbose: bool) -> crate::error::Result<()>`
- When `verbose`, use `Stdio::inherit()` for stderr; on error, use `"(stderr shown above)"` as the stderr string since it was already printed.
- When not verbose, keep current behavior (pipe stderr, capture for error message).
- Update ALL existing callers of `run_git` in sync.rs to pass `false` for the new param in `execute_install` and `execute_update` — then thread verbose through.

Actually, to minimize churn, add `verbose` parameter only to `execute_sync_plan`. Inside `execute_sync_plan`, print SHA info before/after operations when verbose:

```rust
// In the Install match arm, before calling execute_install:

    eprintln!("  {} -> {}", dir_name, &remote_sha[..8.min(remote_sha.len())]);

// In the Update match arm, before calling execute_update:

```

For git command stderr in verbose mode: This is a lower-priority enhancement. The simplest approach that doesn't break the clean `run_git` interface:
- Keep `run_git` as-is (no signature change).
- In verbose mode, before calling execute_install/execute_update, print the git operation being performed.
- Git errors are already shown via the `eprintln!("warning: failed to ...")` lines.

This is a practical trade-off: verbose shows SHA comparisons (the primary user need), while git stderr is shown only on failure (already the case). This satisfies CLI-03 ("shows detailed per-skill output including SHA comparisons").

**Create `.github/workflows/release.yml`:**

Per CONTEXT.md decisions:
- Triggered by version tag push (v0.1.0 pattern)
- Target: macOS ARM (aarch64-apple-darwin) and Linux x86_64 (x86_64-unknown-linux-musl)
- Use `houseabsolute/actions-rust-cross@v1` for building
- Use `softprops/action-gh-release@v2` for uploading

```yaml
name: Release

on:
  push:
    tags:
      - "v[0-9]+.[0-9]+.[0-9]+"

permissions:
  contents: write

jobs:
  build:
    name: Build ${{ matrix.platform.name }}
    runs-on: ${{ matrix.platform.runs-on }}
    strategy:
      matrix:
        platform:
          - name: macOS ARM64
            runs-on: macos-latest
            target: aarch64-apple-darwin
          - name: Linux x86_64
            runs-on: ubuntu-latest
            target: x86_64-unknown-linux-musl
    steps:
      - uses: actions/checkout@v4

      - uses: houseabsolute/actions-rust-cross@v1
        with:
          command: build
          target: ${{ matrix.platform.target }}
          args: "--locked --release"
          strip: true

      - name: Package binary
        shell: bash
        run: |
          VERSION="${GITHUB_REF#refs/tags/}"
          TARGET="${{ matrix.platform.target }}"
          BINARY="skills-sync"
          ARCHIVE="${BINARY}-${VERSION}-${TARGET}.tar.gz"
          cp "target/${TARGET}/release/${BINARY}" "${BINARY}"
          tar -czf "${ARCHIVE}" "${BINARY}"
          echo "ARCHIVE=${ARCHIVE}" >> $GITHUB_ENV

      - uses: softprops/action-gh-release@v2
        with:
          files: ${{ env.ARCHIVE }}
```
