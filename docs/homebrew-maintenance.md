# Homebrew tap maintenance

This document is for the repository owner and release maintainers. User-facing install, upgrade and uninstall commands live in the [README](../README.md#install).

The end-user command is:

```sh
brew install benvds/tap/skill-sync
```

That shorthand resolves to the public tap repository `benvds/homebrew-tap` and its `Formula/skill-sync.rb` formula. The tap name is `benvds/tap`; keep the README, tap and formula pointing at the same name.

## Publication and verification status

Publishing the tap is an owner action outside this repository's automation. This table describes the `v1.0.0` formula snapshot; update it when the owner publishes or re-verifies the tap.

| Check | State |
|---|---|
| Formula matches the published `v1.0.0` release assets | Verified: both archive URLs, file names and SHA-256 values match the published archives and sidecars |
| Formula structure and checksum format | Verified offline by `python3 scripts/homebrew.py --check` and `tests/test_homebrew.py` |
| Tap repository and formula published | Owner action: create `benvds/homebrew-tap` and publish `Formula/skill-sync.rb` (see below) |
| Fresh install, `skill-sync --version`, upgrade and uninstall through Homebrew on macOS Apple Silicon | Owner verification required; not performed for this snapshot |
| Fresh install, `skill-sync --version`, upgrade and uninstall through Homebrew on Linux x86_64 | Owner verification required; not performed for this snapshot |
| Direct invocation of the published Linux x86_64 archive | Verified by extracting the `v1.0.0` archive and running `skill-sync --version`; this is not a Homebrew install check |

The tap, Homebrew installation, upgrade and uninstall checks must not be reported as complete until the owner runs the validation checklist on both supported platforms.

## Formula source of truth

`Formula/skill-sync.rb` in this repository is the reviewed formula snapshot. It is generated by `scripts/homebrew.py` from the versioned GitHub Release archives and their `.sha256` sidecars:

```sh
python3 scripts/homebrew.py --check
python3 scripts/homebrew.py --update --tag v1.2.3
```

`--update` downloads the two sidecars, validates their filenames and 64-character SHA-256 digests, and rewrites the formula. `--check` works offline and rejects hand-edited or structurally invalid formulas. Do not edit the URL or checksum lines by hand.

The formula supports only the archives produced by the release workflow:

| Platform | Release target |
|---|---|
| macOS Apple Silicon | `aarch64-apple-darwin` |
| Linux x86_64 | `x86_64-unknown-linux-musl` |

It declares `depends_on "git"` and installs the `skill-sync` binary with `bin.install`; users do not need a Rust toolchain. The `test do` block runs `skill-sync --version`.

## One-time tap setup

The tap repository is separate from this checkout. Create it once under the owner account if it does not exist:

```sh
gh repo create benvds/homebrew-tap --public \
  --description "Homebrew formulae for benvds projects"
git clone https://github.com/benvds/homebrew-tap.git
mkdir -p homebrew-tap/Formula
cp Formula/skill-sync.rb homebrew-tap/Formula/skill-sync.rb
cd homebrew-tap
git add Formula/skill-sync.rb
git commit -m "skill-sync 1.0.0"
git push origin main
```

A tap needs no special repository settings beyond being public. Add a short tap README if desired, for example:

```markdown
# benvds Homebrew tap

    brew install benvds/tap/skill-sync
```

If `main` is protected, allow the owner or the dedicated automation identity to merge the formula update. Homebrew reads the tap's default branch.

## Credentials and repository settings

The default manual flow needs no CI credentials. The owner needs write access to `benvds/homebrew-tap`, and the tap must be public so users can install without authentication.

Release automation needs separate credentials because a GitHub Actions workflow's built-in `GITHUB_TOKEN` is scoped to `benvds/skill-sync` and cannot push to the tap:

- Create a fine-grained personal access token with repository access limited to `benvds/homebrew-tap`.
- Grant **Contents: Read and write** and **Metadata: Read** only. Do not grant administration, workflows or access to unrelated repositories.
- Store it as the `HOMEBREW_TAP_TOKEN` Actions secret in `benvds/skill-sync` under **Settings → Secrets and variables → Actions**.
- If the tap branch is protected, either allow that identity to bypass the rule or have automation open a pull request instead of pushing directly.
- If a deploy key is used instead, scope it to `benvds/homebrew-tap` with write access and store only the private key as a secret. Prefer one tap-scoped credential over a broad classic token.

The current release workflow does not use this secret and does not publish to the tap. Adding cross-repository publication would expand the release workflow's write access; treat that as a separate reviewed change.

## Publishing the initial formula

The checked-in formula was generated from the published `v1.0.0` assets:

```text
skill-sync-v1.0.0-aarch64-apple-darwin.tar.gz
  e1254fc3e06ed908571c277654228981e8008c867c8c79763f42c6ba5b6c1431
skill-sync-v1.0.0-x86_64-unknown-linux-musl.tar.gz
  6ca80274eee54c294910d18355708146f28851857c1e98268b627053dfbce1ed
```

Before publishing:

1. Confirm both archive and `.sha256` sidecar assets exist on the GitHub Release.
2. Run `python3 scripts/homebrew.py --check` and, if the snapshot needs regenerating, `python3 scripts/homebrew.py --update --tag v1.0.0`.
3. Compare the generated URLs with the release page and confirm the sidecars match the downloaded archives. Do not copy a checksum from a different release.
4. Test the formula from a checkout before pushing it to the tap:

   ```sh
   brew install --formula ./Formula/skill-sync.rb
   skill-sync --version
   brew test skill-sync
   brew uninstall skill-sync
   ```

5. Copy `Formula/skill-sync.rb` to `benvds/homebrew-tap`, commit it, and push. Then verify the documented tap command:

   ```sh
   brew tap benvds/tap
   brew install benvds/tap/skill-sync
   skill-sync --version
   brew uninstall skill-sync
   ```

Run the fresh-install check on both macOS Apple Silicon and Linux x86_64 before publishing the tap.

## Updating after a release

The release assets must be published before the formula can be updated:

1. Wait for the tag-triggered release workflow to publish both archives and sidecars. A missing asset makes the update fail rather than producing an unverified formula.
2. Regenerate the formula from the new tag:

   ```sh
   python3 scripts/homebrew.py --update --tag v1.2.3
   python3 scripts/homebrew.py --check
   ```

3. Review `git diff Formula/skill-sync.rb`. The version in both asset URLs and both checksums should change; the dependency, install and test blocks should not.
4. Commit the regenerated snapshot in this repository and copy the same file to `benvds/homebrew-tap/Formula/skill-sync.rb`. Commit and push the tap change.
5. Run `brew update` and verify the upgrade path:

   ```sh
   brew upgrade skill-sync
   skill-sync --version
   brew uninstall skill-sync
   ```

6. Verify a fresh install of the new version on both supported platforms.

What is automated: URL and checksum generation, checksum shape and filename validation, and formula structure checks. What remains manual by design: reviewing the diff, committing the snapshot in this repository, pushing the same formula to the tap, and testing the published tap on both platforms. Automating the tap push requires the scoped credential described above and should run only after the release assets exist.

## Validation checklist

Use a clean Homebrew environment or `brew reinstall` to avoid a cached binary.

- `brew tap benvds/tap` succeeds and the tap is on the default branch.
- `brew install benvds/tap/skill-sync` downloads the versioned archive and reports no checksum failure.
- `skill-sync --version` prints the version in the formula.
- `skill-sync --help` starts successfully without Rust or Cargo.
- `brew deps --installed skill-sync` shows Git, and `brew test skill-sync` passes.
- `brew upgrade skill-sync` moves to the next published formula version.
- `brew uninstall skill-sync` removes the binary; `brew untap benvds/tap` is optional cleanup.

## Recovering from a failed publication

- **Release not published yet:** `--update` cannot find the sidecar. Wait for the release workflow and rerun; do not write a guessed checksum.
- **Checksum mismatch or malformed sidecar:** re-download the archive and sidecar, and compare them locally. If they still disagree, the release is broken. Publish a fixed patch release; do not weaken or bypass the checksum.
- **Wrong URL or 404:** confirm the tag and asset names from the release page. Update with the exact tag; do not switch to an unversioned `latest` URL.
- **Tap push rejected:** the local tap commit is still safe. Fix the owner's write access or branch-protection setting, then push without force. If branch protection requires review, open a pull request.
- **Bad formula already published:** revert the tap commit (`git revert <commit>`), push, and tell users to run `brew update` and `brew reinstall skill-sync` after the fix. The versioned assets remain available for the installer fallback.
- **Deleted or replaced release asset:** restore the exact asset or publish a new patch version. Never replace an existing tag's archive with different bytes, because published checksums and Homebrew caches would disagree.
- **Audit or test failure:** fix the formula and repeat the validation. Do not publish with a skipped audit, test or checksum check.
